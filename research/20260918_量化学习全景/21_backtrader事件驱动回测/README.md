> 环境：工作区自带 .venv，backtrader 1.9.78.123。全部数字来自 `main.py` 实际运行（seed=42，总耗时约 9 秒）。

## 这节课学什么

课02 用 30 行 pandas 向量化代码写了一个 SMA(20)/SMA(60) 双均线回测。这节课把**同一个策略、同一套成本假设**（佣金双边万2.5 + 印花税卖出千0.5 + 滑点单边 0.1%）搬进工业级事件驱动框架 backtrader，回答一个新手必问、但很少被认真回答的问题：

> **"我用框架跑出来的结果，和我手写的能对上吗？"**

答案分三步（也是本课主线）：

1. **对不齐**：bt 默认市价单在**次日开盘价**成交，手写版隐含在**信号日收盘价**成交——仅这一个细节就让两引擎 11 年累计差出 **13.8 个百分点**；
2. **找原因**：逐笔核对 55 笔成交的日期与价格，定位每一个百分点来自哪条实现规则；
3. **对齐**：把 bt 的成交口径改成 cheat-on-close（用信号日收盘价作为成交基准价）、滑点用 slip_out=True 复现课02的恒定滑点模型后，两引擎年化差 **+0.00pp**、期末净值差 **-0.04pp**、净值路径逐日最大偏差 **0.038%**——**框架没有魔法**。

顺带学会：bt 六件套（Cerebro / Data Feed / Strategy / Broker / Sizer / Analyzer）的实战写法、用同一框架复用实现海龟简化版、optstrategy 参数网格优化及其过拟合风险。

## 核心概念

### 1. 事件驱动 vs 向量化：两种回测范式

| | 向量化（课02） | 事件驱动（backtrader） |
|---|---|---|
| 思路 | "仓位×收益率−成本"整条序列一次算完 | 逐根 bar 推进时钟，每根 bar 依次回调策略的 `next()` |
| 代码量 | 30 行 | 六件套约 300 行 |
| 速度 | 极快 | 慢一个量级（本课 2845 根 bar 单次约 0.1 秒） |
| 表达力 | 仓位变化只能用简化公式近似 | 下单→撮合→扣费→拒单回报全过程可表达 |
| 典型风险 | 前视偏差（信号当日成交）、成本模型失真 | 框架**默认行为**与你的假设不一致（本课主题） |

真实交易系统就是事件驱动地一拍一拍工作的，所以 bt 的策略代码几乎可以原样搬到模拟盘——这是学框架的理由。

### 2. bt 六件套各管什么（对应 main.py 行号）

- **Cerebro（大脑/总调度）**：装数据、策略、经纪商、分析器，`run()` 逐 bar 推进。见 `make_cerebro()`（main.py:456）。★本课实测发现：cerebro 的 `_runnext` 循环里 `broker.next()` 跑在 `strat.next()` **之前**（cerebro.py 源码），所以 coc 订单实际在**下一根 bar 的 broker 环节**成交。
- **Data Feed（数据翻译）**：`bt.feeds.PandasData(dataname=df)`（main.py:477），把 DataFrame 按**列名**自动对到 open/high/low/close/volume，时间取自索引。line 用 `[0]` 取当前 bar、`[-1]` 取上一根。
- **Strategy（策略逻辑）**：`SmaCrossStrategy`（main.py:348）。`__init__` 建指标（只建一次），`next` 每 bar 决策（main.py:372），`notify_order` 接收订单回报（main.py:384），`stop` 收尾。
- **Broker（模拟券商）**：初始现金 100 万（main.py:478）、挂佣金表（:479）、设滑点（:481）、coc 开关（:483）。佣金、滑点、撮合、拒单全是它管。
- **Sizer（下单数量计算器）**：`AllInSizer`（main.py:287，满仓买入）、`TurtleSizer`（main.py:321，ATR 风险仓位）。策略只说"买"，买多少股由 Sizer 决定。
- **Analyzer（绩效统计器）**：注册与取数见 `add_analyzers()`（main.py:488-506）：Returns（几何年化）、SharpeRatio_A、DrawDown、TradeAnalyzer、TimeReturn。

### 3. "次日用什么价格成交"——为什么这一个细节差出十几个点

课02 手写版的机制是 `pos = signal.shift(1)`：t 日收盘算出信号，**t+1 日起新仓位才参与结算**。这意味着 t+1 的收益恰好是 close[t]→close[t+1] 这一段，**隐含成交价 = 信号日 t 的收盘价**（相当于收盘集合竞价下单）。

bt 默认市价单则是：t 日收盘后 `next()` 里下单 → **t+1 日开盘价成交**。

两个"明天执行"的实现，一个锚定昨收、一个锚定明开。平安银行隔夜跳空经常 ±2% 以上，每笔交易平均差出千分之几，27 笔往返、11 年复利下来：

- **对齐前：年化 1.84%（手写） vs 0.77%（bt默认），累计 22.90% vs 9.07%，差 -13.83pp，净值路径最大偏差 11.87%。**
- bt默认版还叠加一个次要因素：下单时不知道明天的价格，满仓买入必须为"可能高开到涨停 +10%"预留约 10% 现金（`AllInSizer` 的 safety=0.90，main.py:292-301），这部分现金不吃收益；手写版的分数仓位没有这个问题。

对齐的方法：`cerebro.broker.set_coc(True)` 让市价单以**下单当根 bar 的收盘价**为成交基准价。对齐后 bt coc 与手写参考版年化差 **+0.00pp**、期末净值 1.2286 vs 1.2290（差 -0.04pp）、净值路径逐日最大偏差 **0.038%**——残余偏差就是整数股取整的零头现金（每股约 11 元）。

### 4. 框架的好处与代价

- **好处**：成本、撮合、仓位、绩效统计全部交给框架，策略文件里只剩信号与决策；订单状态机（未完成订单互斥锁）天然正确；换一个策略（海龟）只换 Strategy + Sizer 两个类，Broker/Analyzer/绘图管线全部复用（图3）。
- **代价**：每个细节都被框架的**默认实现**接管——默认值和你的想法不一致时（默认次日开盘成交、滑点默认不出界、市价单默认不上滑点、夏普默认年度口径），你必须钻进源码核对口径。本课验证一致性的过程，就是把 bt 四个默认行为逐一核对并显式配置的过程。

## 常见的坑（本课全部踩过并写进代码）

1. **bt 默认次日开盘成交**。`next()` 里的 `self.buy()` 是市价单，默认在**下一根 bar 的开盘价**成交，不是"明天按信号价成交"，更不是"今天收盘成交"。想锚定信号日收盘价要 `cerebro.broker.set_coc(True)`（cheat-on-close）。本课实测这个默认行为造成 -1.07pp 年化 / -13.83pp 累计的偏差。
2. **cheat-on-close 的滥用**：coc 是"作弊"参数——现实中你无法确定以收盘价成交（收盘竞价只能近似）。它可以用来做**口径对齐**（本课），但绝不能拿来"美化"策略收益后直接报告；报告前想清楚你的真实执行方式更接近开盘价、收盘价还是均价。另外 coc 是 **Broker 的参数**（`cerebro.broker.set_coc`），不是 Cerebro 构造参数；而且本课还发现：由于 cerebro 的 `_runnext` 里 broker 环节先于策略环节运行，coc 订单实际在**下一根 bar 的 broker 环节**成交——成交价基准是信号日收盘，但滑点钳制用的是**次日**的 high/low，连这个细节都要对齐。
3. **印花税表达不了"卖出单向"**：bt 内置佣金是双边对称的，`setcommission(commission=...)` 写不出"卖出加收千0.5"。绕法：继承 `bt.CommInfoBase` 重写 `_getcommission(self, size, price, pseudoexec)`（main.py:259-285）——`size < 0`（卖出）时额外加 `abs(size)*price*STAMP_TAX`。注意三个细节：`stocklike=True`（股票全额现金）、`percabs=True`（佣金数值按绝对小数理解，默认 False 是"百分数"口径，会差 100 倍）、`pseudoexec=True` 时是试算不能有副作用。另外佣金按**含滑点的成交价**计提，滑点归 Broker 的 `set_slippage_perc` 管，别混进佣金。
4. **滑点的三层开关**（main.py:481）：`slip_open=True` 才对市价单生效（默认 False 时市价单**根本不上滑点**——实测 1 股订单验证）；`slip_match=True`（默认）会把滑点价钳回**成交 bar** 的 high/low 内（物理上合理：不可能以超出当日波幅的价格成交），但对齐课02的恒定滑点模型要 `slip_out=True`；`slip_out=True` 允许出界价成交（不真实但与手写模型一致）。**手写引擎要和 bt 用同一条规则**，本课两套规则都做了对齐验证。
5. **`cerebro.plot()` 报错**：bt 1.9.78.123 的 plot 与新版 matplotlib 不兼容（locator/字体问题）。绕法：全程 `matplotlib.use('Agg')` + 自己画图——净值/回撤用 `TimeReturn` analyzer 的逐日收益 cumprod 重放，买卖点从 `notify_order` 里的 `order.executed` 收集。
6. **analyzer 的夏普口径不同**：`SharpeRatio_A` 默认 `timeframe=Years` → 用**年度收益**算夏普、`riskfreerate` 默认 **1%**（不是 2%）、总体标准差（非样本）、年化因子处理也不同——和手写版"日收益年化、rf=2%、ddof=1"是两套口径，直接对表必然对不上（本课 CSV 里同时给两列：bt原生口径 0.112 vs 同口径 -0.007）。要做严格对表：用 `TimeReturn` 取逐日收益，按手写同公式自己重算（main.py:509-570），或显式给 `SharpeRatio` 传 `timeframe=Days, riskfreerate=0.02, annualize=True`。同类坑：`Returns.rnorm` 的年化公式恰好与手写版一致（几何均值×252），可以直接比；`DrawDown` 的 `max.drawdown` 是**正的幅度**；`TradeAnalyzer` 的"笔数"是**完整往返**（与手写的"开+平事件数"差一倍），且期末未平仓位计入 `total.open`、不计入胜率分母。

## 延伸思考（练习）

1. **把对齐反过来做**：保持 bt 用默认次日开盘成交，把 `hand_engine()` 改成"信号次日开盘价成交"（t+1 日收益从 open[t+1] 到 close[t+1]，卖出在 s+1 开盘），再对一次账。提示：bt默认版因 Sizer 预留 10% 现金无法真正满仓，你还需要给手写版加上同样的 90.9% 仓位上限才能严格对齐——体会"次日开盘成交"模式下"数量必须提前确定"的代价。
2. **给海龟补全**：加 2N（2×ATR）移动止损、每 0.5N 加仓一个单元（最多 4 单元），用 `bt.ind.ATR` 与 `notify_trade` 实现；对比简化版（期末 1.1160、回撤 -17.08%）的收益/回撤变化，并检查加仓逻辑下 `TradeAnalyzer` 的笔数还等不等于"开仓次数"。
3. **过拟合体检**：把网格从 28 组加密到 7×13=91 组（快线步 5 不变、慢线步 10），观察最优组合的年化从 6.38% 涨到哪里；再把数据切成 2015-2020 / 2021-2026 两段分别跑同一组最优参数，看年化的稳定性——用"样本外衰减"给网格最优参数打分（呼应课07/课16）。
