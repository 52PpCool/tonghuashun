# 40 纸面交易运行器：让策略"活"过来（量化工程篇②）

> 数据：5 只池（平安银行/贵州茅台/中兴通讯/北方华创/中际旭创），新浪源前复权日K（联网刷新至 2026-09-30，国庆前最后交易日）。
> 环境：全景课 `.venv`。全部数字来自实际运行，产出在 `outputs/` 与 `data/paper.db`。
> **合规声明：纯纸面交易（paper trading），不连接任何真实券商接口，不构成投资建议。**

## 这节课学什么

前 39 课的所有策略都是"跑完即死"的研究脚本。本课写一个**每天盘后自动跑的活系统**：
恢复状态 → 开盘撮合昨日挂单 → 收盘算信号 → 提交订单 → 估值 → **对账**。
对程序员而言这一课全是主场技术（SQLite/状态机/幂等/对账），但每个环节都被赋予了
金融语义——这正是量化的工程难点：**时序纪律**。

## 1. 系统结构

```
main.py        CLI：--init 建库 / --live-refresh 联网刷新 / --backfill 回放 / --date 单日 / --report 对账
store.py       SQLite 七表：instruments / daily_prices / signals / orders / fills / account_daily / run_log
signalcalc.py  SMA20/60 信号（与课02/39 同款；只准用截至今天的数据）
broker.py      纸面撮合台：**直接调用 quantlab.engine.fill_order**——与39课回测引擎同一函数
reconcile.py   五条不变式（见 §4）
datafeed.py    新浪源取数（限速1s+指数退避；前复权增量陷阱见下）
```

**每日时序纪律**（防前视的工程实现）：T 日收盘后算信号 → 提交订单（`PENDING`）→
T+1 日开盘撮合。代码里没有一行注释能阻止你用今天收盘价算信号今天成交——
是"信号只在收盘步计算、订单只在次日开盘步撮合"的**流程结构**在阻止它。

**复权陷阱（datafeed.py 的核心教训）**：前复权序列会在每次分红除权后**整体重算**，
"只拉尾部增量拼到旧历史上"必然错位。正确做法：前复权全量重拉整表替换（5只约15秒）；
只有**原始价**才允许真增量（第41课建仓用）。

## 2. 实战中抓到的两个真 bug（本课最值钱的部分）

这两个 bug 都是回填演示**第一次运行就暴露**的，修复过程全程留痕：

**Bug1 拒单不落库 → 重复成交**。07-31 开盘撮合拒了订单7，但只有 `new_fills`（成交）
被写回 DB，拒单状态留在内存——重启后 DB 里它还是 `PENDING`，与 07-31 重挂的新单
在 08-03 **双双成交**（同一只股票买了两份，对账五条不变式竟全部"通过"——因为账是自洽的，
错的是行为）。修复：撮合后 FILLED 与 REJECTED 都即时持久化。**教训：状态机的每次
状态迁移都必须落库，"内存态"和"DB态"分离就是事故温床。**

**Bug2 浮点往返把 100 股算成 0 股**。撮合时 `budget = shares×px` 再 `int(budget/px/手数)`
反推股数——`133136.003 / 1331.36003` 在浮点下 = `99.9999...` → `int()` = 0 手 → 一笔完全
付得起的订单被误拒 `NO_CASH`。回测里这是无害的静默缩量（39课的海鼠基线因此被缩了
一点手数，12.06%→修复后 12.24%），在实盘路径上就是事故。修复：指定股数直接用，
现金只作上限收缩。**教训：数量语义不要"乘完再除回来"。**

**Bug3（彩蛋）模块名 `signal.py` 遮蔽标准库**：`import pandas` 级联崩溃——Python 的
`signal` 模块被本地文件遮蔽。改名 `signalcalc.py`。

## 3. 回填演示（2026-06-01 ~ 2026-09-30，86 个交易日）

SMA20/60 择时、5 只等权（每只目标 20%）、成本口径与课02/39 一致：

| 指标 | 值 |
|---|---|
| 期末权益 | **1,019,704.43（+1.97%）** |
| 订单 | 9 笔全部成交，0 拒单 |
| 总费用 | 679.97 元（佣金+印花税） |
| 对账失败项 | **0** |

订单流水的叙事（outputs/orders.csv）：6/1 开仓买入 000063/002371/300308；
7/21 卖出 000063（SMA 死叉）；7/28 买入 000001；7/31 买入 600519；8/21 卖出 002371；
9/23 卖出 600519。其中 600519 一单的成交价 1351.95 = 08-03 开盘价——
07-31 是周五，订单穿过周末在 08-03（周一）开盘成交，时序纪律肉眼可见。

**幂等性实测**：`--date 2026-09-30` 重跑后订单总数不变（无重复下单）、权益分毫不差——
重跑日只重算信号与快照，订单提交被 `orders WHERE date=?` 守卫拦截。

## 4. 对账：运行器的免疫系统（reconcile.py）

每天收盘估值后跑五条不变式，任何失败写 `run_log(ok=0)`：

- **I1 现金恒等式**：equity == cash + Σ持仓×最近收盘（估值口径一致）
- **I2 现金非负**（无融资）
- **I3 持仓非负**
- **I4 订单-成交一一对应**：FILLED 订单恰有 1 条 fill；REJECTED 必有 reason
- **I5 数据新鲜度**：当日 5 只池全有行情（停牌需显式标注）

86 天全部全绿。注意 Bug1 的"重复成交"之所以能发生，正是因为它不违反这五条——
**对账管账自洽，不管行为正确**；行为正确性靠状态机纪律（每次迁移落库）。

## 5. 诚实边界

- 纯纸面：无真实券商通道、无实盘滑点冲击、未接收盘竞价/集合竞价机制。
- 撮合价用次日开盘价+恒定滑点近似；真实开盘集合竞价的价格形成不同（课19/30）。
- 目标权重 20% 只在"空仓→开仓"时执行，持仓期间不做再平衡（仓位漂移保留）；
  再平衡的数学见课18。
- `--live-refresh` 每次全量重拉前复权（约15秒/5只），池子扩大需改任务调度与限频。
