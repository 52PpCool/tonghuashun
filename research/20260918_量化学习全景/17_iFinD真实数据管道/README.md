## 1. 这节课学什么

前面 16 课的数据都来自 `data/cache` 的静态 CSV——干净、整齐、列名统一，**真实世界没有这种好事**。这节课你将第一次对接真实的商业金融数据接口（iFinD），体验机构里数据工程师的日常：

1. **取数**：用自然语言向接口要数据（智能选股 + 财务指标 + 行情指标）；
2. **留痕**：每个原始响应原样落盘，出问题能回溯、能审计；
3. **解析**：接口返回的不是 DataFrame，是三层嵌套的 JSON 包着 markdown 表格——自己动手拆；
4. **清洗**：同一个查询两次调用返回结构都不一样，去重、取最新、补缺值样样不能少；
5. **打分**：质量 × 估值 × 动量三因子等权合成，选出前 10 名；
6. **对照**：拿本地缓存数据做同口径验证，理解"接口的时效性 vs 缓存的静态性"。

学完这课，你就完成了从"用现成干净数据做策略"到"从源头获取脏数据并加工成策略可用形态"的跨越——这是量化研究和量化工程的分水岭。

## 2. iFinD 接口是什么、怎么调

**iFinD** 是同花顺旗下的专业金融数据终端（面向机构/研究员），本工作区已配置好它的 MCP 数据服务，通过一个 Node 封装脚本即可调用，无需自己处理鉴权和 HTTP 细节。核心函数只有一个：

```js
const { call } = require('/home/ppku/zcodespace/tonghuashun/.zcode/skills/ifind-finance-data/call-node.js');
const result = await call(server_type, tool_name, params);
// server_type: "stock"（本课只用这个）/ "fund" / "edb" / "index" ...
// params:      { query: "自然语言描述你要什么数据" }
```

本课用到的三个 stock 工具：

| 工具 | 干什么 | 本课的 query |
|---|---|---|
| `search_stocks` | 智能选股（自然语言筛股票） | `沪深300成分股中市值大于500亿的股票` |
| `get_stock_financials` | 财务数据与指标 | `工商银行、农业银行、……的最新ROE、净利润增速、市盈率、资产负债率` |
| `get_stock_performance` | 日频行情与技术指标 | `工商银行、农业银行、……的最新收盘价、近60日涨跌幅` |

**一次真实调用的完整代码**（节选自本目录 `fetch_ifind.js`，可直接运行）：

```js
const { call } = require('/home/ppku/zcodespace/tonghuashun/.zcode/skills/ifind-finance-data/call-node.js');
const fs = require('fs');

async function main() {
  const result = await call("stock", "search_stocks",
    { query: "沪深300成分股中市值大于500亿的股票" });
  fs.writeFileSync('raw/01_search.json', JSON.stringify(result, null, 2));  // 留痕
  console.log(JSON.stringify(result, null, 2));
}
main();
```

**返回结构长什么样**（这是本课第一个大坑）。`result` 是 MCP 协议的 JSON-RPC 响应，数据藏在最深处，像俄罗斯套娃：

```
result.data.result.content[0].text     ← 第1层：MCP包装，text 是一段 JSON 字符串
  ↓ JSON.parse
{"code":1, "msg":"success",
 "data": "{\"answer\":\"...\"}"}       ← 第2层：业务包装，data 又是一段 JSON 字符串
  ↓ 再 JSON.parse
{"answer": "# 选股结果及选股依据数据\n\n| 股票代码 | 股票简称 | 股票市场类型 | 总市值[20260918] |...",
 "dataTotalVolume": 1048,
 "selectedSecuritiesCount": 262}       ← 第3层：真正的内容——markdown 表格文本 + 元信息
```

也就是说：**你以为拿到的是数据，实际拿到的是"装在 JSON 里的 JSON 里的 markdown 表格文本"**，必须连拆三层再用文本方式解析表格。`fetch_ifind.js` 里的 `unwrapToMarkdown()` 和 `parse_and_screen.py` 里的 `unwrap_text()` 就是干这个的。

几个必须知道的元信息：

- **限流**：免费 key 每秒最多 2 个请求。本课每次调用后 `sleep(1100)` 毫秒，并控制全程 **9 次调用**（1 次选股 + 4 批财务 + 4 批行情）。
- **单次 query 主体别超过 5 个**：自然语言解析对长 query 不稳，所以 20 只股票要拆成 4 批、每批 5 只。
- **结果截断**：选股命中 262 只时，返回文本里只给了前 100 行，同时附一个 **24 小时有效的全量 CSV 下载链接**（`raw/01_search_full.csv`，13,383 字节，262 行）。下载不算接口调用、不受限流。

## 3. 数据管道的设计

```
fetch_ifind.js (取数+留痕)                parse_and_screen.py (解析→清洗→打分→输出)
┌─────────────────────────┐            ┌──────────────────────────────────────┐
│ search_stocks           │──raw/01_*.json──→ 拆三层JSON → 解析markdown表格     │
│ 下载全量CSV(262只)       │──raw/01_*.csv──→  候选池(市值列排序取前20)          │
│ get_stock_financials ×4 │──raw/02_*.json──→  PE表+ROE表 → 按表头名归并        │
│ get_stock_performance ×4│──raw/03_*.json──→  行情表 → 每代码保留最新日期一行   │
└─────────────────────────┘            │ 合并 → 去重/缺值统计/类型转换          │
                                       │ z-score三因子打分 → 前10名             │
                                       │ outputs/*.csv + 3张PNG + 缓存对照     │
                                       └──────────────────────────────────────┘
```

每一步为什么必要：

| 步骤 | 为什么必要 |
|---|---|
| **取数分批（≤5主体/次）** | 单次 query 塞太多主体，自然语言解析容易漏指标甚至失败；拆批还能把失败影响限制在一批内 |
| **留痕（raw/ 原样存盘）** | 接口返回结构会变、会截断、会失败。没有原始响应，出了问题既没法查也没法复现。这是合规审计的基本要求 |
| **下载全量CSV** | 返回文本截断到 100 行时，全量 CSV 是唯一能拿到完整 262 只的途径（且不消耗调用次数） |
| **按表头名解析而非按列位置** | 实测同一查询不同批次返回的**列顺序不一样**（某批"资产负债率"排在"净利润增速"前面）。按位置取数迟早拿错列 |
| **"每代码保留最新一行"去重** | 行情接口有时返回每股 1 行的快照，有时返回每股几十行的时间序列（见第 7 节）。合并前必须显式选最新，否则一股变多行、打分全错 |
| **缺值统计 + 类型转换** | `%`、千分位逗号、`-`、科学计数法 `2.27E11` 混在一个单元格列里；缺值不统计，下一环节就会静默产出错误结论 |
| **z-score 等权打分** | ROE 是百分数、市值是亿元，量纲不同不能直接相加。标准化到同一尺度后等权合成：质量分=(z(ROE)+z(归母增速))/2，估值分=−z(PE)，动量分=z(60日涨幅)，综合分=三者均值 |
| **输出 utf-8-sig** | 带 BOM 的 CSV 用 Excel 双击打开中文不乱码 |

## 6. 对照实验：接口数据的时效性 vs 缓存数据的静态性

`data/cache/` 里有 30 只 A 股日线（akshare/yfinance 下载）。缓存**只有 OHLCV，没有 ROE/PE**，所以"同口径打分"只能做到动量维度——这本身就是最重要的结论：**没有实时数据接口，质量和估值因子根本无从谈起**。

实际对照结果（`outputs/cache_vs_ifind.csv`）：

- 30 只缓存股票中 **29 只**在 262 只候选池内（唯一例外：万科 A，市值已跌破 500 亿门槛被筛掉——静态缓存反映不了这种基本面变化）；
- 与 20 只深挖名单重叠 **10 只**；这 10 只的近 60 日涨幅：iFinD（截至 2026-09-18）与缓存（截至 2026-09-17）**Spearman 秩相关 ρ=0.952（p≈0.000）**——口径基本一致；
- 但逐只看有系统性偏差：iFinD 动量普遍比缓存低 **0.5~3.6 个百分点**（如招商银行 12.03% vs 15.14%、中国石油 19.86% vs 23.43%），收盘价差在 **−0.92% ~ +1.65%** 之间——因为两边隔着 1 个交易日（缓存 30 只中 24 只截至 09-17、6 只更新到 09-18，如长江电力/美的集团）。

**结论**：缓存数据"差一天、错三点"，做策略回测够用；但做**今天的**选股决策，必须用接口取今天的数。这就是机构愿意为数据接口付费的原因。

## 7. 常见的坑（每一条都是本次运行真实踩过/防过的）

1. **接口限流**。免费 key 每秒最多 2 个请求，超了直接报错。对策：每次调用 `sleep(1100)` 毫秒；能合并的指标合并在一个 query 里（一次查"ROE、增速、PE、负债率"4 个指标只算 1 次调用）；全程控制在 9 次。
2. **三层嵌套 JSON + markdown 表格解析陷阱**。返回不是结构化数据，是"JSON 套 JSON 套 markdown 文本"：必须连拆三层；表格里有 `|---|---|` 分隔行、单元格两端空格、`2.27E11` 科学计数法、`%` 后缀、`-` 占位符；同一批返回里还有**两张表**（PE 一张、ROE/增速/负债率一张）。任何一步想当然都会解析出空表。
3. **财务数据的滞后性**。PE(TTM) 基于已披露的过去四个季度财报，ROE 是最新**报告期**口径（本例银行股是半年度未年化值，直接和年化比较会错 4 倍量级）；财报每季度才更新一次，而价格每天都在变——**"财报里的 PE 早已过时"**。用基本面打分时要清楚自己用的数字截至哪天（iFinD 的表头会标注，如 `总市值[20260918]`）。
4. **同一个查询，返回结构不稳定**。本课三次运行"最新收盘价、近60日涨跌幅"，行情接口分别返回了：每股 1 行的快照（880 字节）、每股几十行的时间序列 400 行（6,550 字节）、以及**同一次运行内批 1-3 是快照而批 4 是时间序列**（115 行）的混合体。三次的最终前 10 名完全一致——因为清洗里有显式的"每代码保留日期最新一行"。教训：**不要假设接口返回形状，要假设它会变**。
5. **列顺序与列名漂移**。财务表某批次"资产负债率"排在"净利润增速"前面，另一批顺序又反过来；表头有时带 `（单位：%）`有时不带。对策：只按表头名归一化映射，绝不按列号取数。
6. **结果截断**。262 只只展示 100 行，提示"触发截断"并附 CSV 下载链接（24 小时有效）。链接过期后重跑必须重新调用接口——这就是留痕的价值：`raw/01_search_full.csv` 已把全量数据固化在本地。
7. **"N日涨跌幅"的含糊性**。query 里写的是"近 60 日"，返回表头却是 `N日涨跌幅`——N 到底是几，接口没明说（与缓存口径对照 ρ=0.952 佐证它确实是 ~60 交易日）。指标定义一定要用对照数据交叉验证，不能只看表头。
8. **单位与口径**。总市值返回的是"元"（`2.27E11` = 2270 亿），不除以 1e8 图表就全是天文数字；增速有两个口径（净利润 vs 归母净利润，中际旭创 247.29 vs 241.70），本课统一采用更标准的**归母**口径。

**降级方案实测**：`FORCE_FALLBACK=1 python parse_and_screen.py` 已跑通——用 `data/cache` 30 只股票完成动量单因子打分（前 3 名：中国石油 +23.43%、紫金矿业 +22.49%、迈瑞医疗 +18.26%），并显著提示"本次未使用 iFinD、缓存无财务字段故质量/估值分缺省"。接口一旦不可用，流程照样能出结果、能交差。

## 8. 延伸思考（练习）

1. **换打分函数**：把 z-score 换成截面秩百分位（`rank(pct=True)`）重算前 10 名，对比两种方法的重合度。哪个对极端值更稳健？（提示：看中际旭创 +241% 增速在两种方法下的贡献差异。）
2. **成本核算**：把深挖名单从"市值前 20"扩展到全池 262 只，需要多少批、多少次调用、多少分钟（每次间隔 1.1 秒）？如果你是基金经理，免费额度够吗？由此理解为什么机构买 Wind/iFinD 全权限。
3. **加一个新因子**：仿照现有代码，用 `get_stock_performance` 多查一个指标（如"近 20 日涨跌幅"或"换手率"），做成第四个因子，等权并入综合分，观察前 10 名变动。注意：多一个因子 = 调用次数不变（指标塞进同一个 query）但解析逻辑要多处理一种表头。
